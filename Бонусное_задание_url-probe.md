## Задание 3. Мониторинг и алерт (4 балла)

Метрики url-probe попадают в Prometheus **через Node Exporter**: изучите его textfile collector. Свой HTTP-сервер для метрик писать не нужно.

| №   | Требование | Баллы |
| --- | ---------- | ----- |
| 3.1 | Весь стек поднимается одной командой `docker compose up -d`: url-probe, Node Exporter и Prometheus. В Prometheus видны метрики `probe_*` с меткой `url` для каждого URL из списка | 2 |
| 3.2 | Правило оповещения: если URL недоступен дольше 1 минуты, срабатывает алерт, и в его метках есть этот URL. `promtool check rules` проходит. Покажите, как алерт проходит состояния `pending` → `firing` и снова пропадает, когда сайт начинает отвечать | 2 |

Сайт, который можно «сломать» и «починить», поднимите в том же compose (например, контейнер с Nginx).

Как поднять Prometheus и Node Exporter — в [подсказках](#подсказки-стек-мониторинга).

## Подсказки: стек мониторинга

Если `monitoring/` из ДЗ 3 у вас не сохранился, начните с этой заготовки. Grafana в этом задании не нужна.

```
.
├── compose.yaml
└── prometheus/
    ├── prometheus.yml
    └── rules.yml
```

`compose.yaml`:

```yaml
services:
  node-exporter:
    image: prom/node-exporter:v1.9.1
    command:
      - --collector.textfile.directory=/textfile   # отсюда Node Exporter читает *.prom
    volumes:
      - textfile:/textfile:ro
    restart: unless-stopped

  prometheus:
    image: prom/prometheus:v3.5.0
    volumes:
      - ./prometheus:/etc/prometheus:ro
    ports:
      - 127.0.0.1:9090:9090
    restart: unless-stopped

  # TODO: url-probe — должен писать url_probe.prom в тот же том textfile
  # TODO: сайт, который можно остановить и запустить

volumes:
  textfile:
```

`prometheus/prometheus.yml`:

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s   # как часто вычисляются правила оповещения

rule_files:
  - /etc/prometheus/rules.yml

scrape_configs:
  - job_name: node
    static_configs:
      - targets: [node-exporter:9100]   # имя сервиса из compose
```

`prometheus/rules.yml` — формат описан в [документации](https://prometheus.io/docs/prometheus/latest/configuration/alerting_rules/):

```yaml
groups:
  - name: url-probe
    rules: []   # TODO: ваше правило
```

Что пригодится дальше:

- В отличие от ДЗ 3, Node Exporter здесь не нужен `network_mode: host`: метрики хоста не интересуют, ему нужен только каталог с `.prom`.
- Метрики из файла попадают в Prometheus вместе с остальными метриками Node Exporter: ищите `probe_success` в **Graph** на <http://localhost:9090>. Если их нет, сначала проверьте `curl` к Node Exporter изнутри сети compose и метрику `node_textfile_scrape_error`.
- Проверить конфиг и правила, не ставя Prometheus на машину:

  ```bash
  docker run --rm -v ./prometheus:/etc/prometheus:ro --entrypoint promtool \
    prom/prometheus:v3.5.0 check config /etc/prometheus/prometheus.yml
  ```

  Команда проверяет и файлы из `rule_files`. Монтируйте каталог по тому же пути, что и в compose, иначе `promtool` не найдёт `rules.yml`.
- После правки конфига или правил: `docker compose restart prometheus`.
- Состояние алертов видно на <http://localhost:9090/alerts>. Учтите время: url-probe запускается раз в минуту, Prometheus опрашивает Node Exporter раз в 15 с, а правило ждёт `for`. Поэтому от поломки до `firing` проходит 1–3 минуты.
